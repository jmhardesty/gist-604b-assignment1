## Repository 1

**Repository Name:**  QGIS
**Link:**  https://github.com/qgis

### Purpose
What does this project do?

QGIS is a free and open source geographical information system for visualizing spatial data, cartography, geospatial analysis, and data management.
### Repository Structure
What folders or files stand out?

There is a "test" folder with its own readme about how to set up a test environment to try out changes to the code locally. It also has test data to use.
### Documentation
How helpful is the README?

Very helpful. It lists the purpose of the software, examples of outputs, information about versions and the release cycle, installation, and links to more detailed documentation.
### Activity
Is the repository actively maintained?

Yes, there have been recent updates to the code and answers to issues in the last week.
### Key Observation
One thing this project does well.

This is a well known and highly used open source software, so there are many things that this project does well. One thing I noticed is that there are multiple resources for community input and ways to ask questions if something isn't working. These spaces are active and questions are quickly answered.

## Repository 3
**Repository Name:**  GeoPandas
**Link:**  [https://github.com/geopandas](https://github.com/geopandas/geopandas)

### Purpose
What does this project do?

Extends the capability of the Pandas Python package for data analysis. It adds support for geospatial data to existing Pandas infrastructure.
### Repository Structure
What folders or files stand out?

What stands out to me is how few folders and files there are. Compared to a repository like QGIS, this one looks sparse. It makes sense for this project because it is a much smaller scope than something like QGIS.
### Documentation
How helpful is the README?

The README is pretty short. It is primarily there to send people to the full documentation that they have linked to. It does give an overview of the purpose of the project and their funding source and gives some examples.
### Activity
Is the repository actively maintained?

Yes, there have been recent updates to the code and answers to issues in the last week.
### Key Observation
One thing this project does well.

They have a very helpful and interactive set of examples under "Getting started" in the documentation.

GDAL is a library for reading and writing raster and vector geospatial data.

## Reflection
In 3–5 sentences, explain what you learned about how open source projects are organized.

There is a lot of variation in how they are organized and how many files and folders there are. Some projects have a lot of detail in the GitHub repository itself, while others mainly link to an external website for most of the detail. There seems to be a lot about the structure of the projects that is similar. There are clearly "best practices" that all of these projects are following in similar ways.
